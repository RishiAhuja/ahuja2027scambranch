## Notes on methodology

- Final dispositions taken from `private_manifest.jsonl` / `summary.json` (not from ablation snapshot `dispositions_semrev03_langscore.json`, which has different counts).
- Semantic fail-once uses the OR of stored `reviews.semantic` and `reviews.semantic_v02` check results; overwritten intermediate review rounds are not on disk.
- `provenance.review_status` collapses accepted+repaired to `accepted`; use `disposition` for the three-way split.
- Domain one-liners for families come from `scenarios/draft/*/README.md` catalog tables, cross-checked against JSON cards; evidence column paraphrases `label_rationale`.
- Audit stage has 0 ledger rows because `configs/generation.yaml` sets `audit_sample: 0.0`.
- `configs/generation.yaml` sets `max_repair_rounds: 2`, but 113 repaired calls have `repair_history` entries with `round` 3 or 4 (likely from later patch/re-review passes that appended to history). The table reports the observed max round, not the config cap.
- 24/2880 conversations list `repair: claude-haiku-4-5` in `generation_settings.models` (OpenAI empty/truncated repair fallback); the other 2856 list `gpt-6-luna`.
